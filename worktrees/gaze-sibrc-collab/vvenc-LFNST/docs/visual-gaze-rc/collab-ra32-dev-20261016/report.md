# RA32 / 32帧：条带预算与冻结 SIBRC C4 协同开发试验

独立分支：`codex/gaze-sibrc-collab`，实现提交 `52a8a52b`。试验使用 DrivingInCity、DrivingInCountry 两条既有开发序列，不是独立泛化验证。

## 设置与隔离

GOPSize=32，实际编码32帧，NumRefPics=1，四档目标码率逐点复用原32帧 CQP 结果。原 Anchor/C4/条带结果只在四项代表性码流回归通过后复用。C4 模型、统计文件、beta=5、偏移范围[-2,+2]冻结。

`mixed = max(1, round((1-alpha)*original + alpha*strip))`：先混合目标预算，只执行一次 VTM 参数估计，再由原 SIBRC 决定最终 QP/lambda。两者接收同一实际 CTU 比特反馈，全局预算只扣减一次。

远端独立目录 `/root/gaze_sibrc_collab_20261016`；原两个方法的源码、二进制、模型、统计文件和归档结果均未覆盖。四路独立串行编码并发，RAM 预留上限24GB，另核查实际可用RAM和内存盘。

## 结论

16/16 点、两序列四档均完成。两个alpha的四项平均BD-rate均高于单独SIBRC，未满足用户“average不高于SIBRC”的要求；没有选出晋级候选，不开展14序列搜索。协同机制已实际生效，但这条软预算串接路线在本次开发输入上没有边际收益。

| 平均绝对码率误差（%） | SIBRC | H0.10 | H0.25 |
|---|---:|---:|---:|
| DrivingInCity | 0.784639 | 0.610458 | 0.734342 |
| DrivingInCountry | 0.715778 | 0.804320 | 0.975786 |

可观察事实：DrivingInCity R1码率接近SIBRC，H0.10的S-PSNR降低约0.080dB、H0.25降低约0.199dB；提高alpha使两个序列的BD-rate退化加大。存在其他单点小幅增益，但完整曲线均退化。

推断：条带先验改变了VTM基准QP/lambda，原SIBRC的有限偏移未完全补偿其资源转移。当前日志只证明目标和动作同时生效，尚不能唯一归因为预算冲突或fallback；后续需按帧层级与纬度拆解真实比特/失真，再决定是否设计“条带管理行预算、SIBRC行内优化”的第二路线。本轮不修改模型、不按序列调alpha，不把相对Anchor的收益当成相对SIBRC的提升。

最终Python全量回归28/28通过，断点恢复复核16/16通过，230400个CTU交叉核验；16个协同码流均与对应单独SIBRC及条带码流不同。归档SHA见evidence-archive.json。
